## 1. Epic基本信息

- **Epic ID**: EPIC-001
- **Epic名称**: 团队任务管理系统
- **业务背景**: 
  - 当前痛点：12人软件开发团队存在严重的协作混乱问题，具体表现为：任务分配不明确导致责任推诿、项目进度不透明、沟通信息散落在微信/邮件/会议中难以追溯、任务清单分散在Excel/笔记本/Trello等多个工具中（来自会议纪要 - 1.3 核心协作痛点具体化）
  - 业务驱动：团队规模从12人预计扩展到20-30人，现有混乱状态将严重影响团队执行效率和项目交付质量（来自会议纪要 - 1.1 团队规模与组织结构）
  - 提出部门：研发团队（来自会议纪要 - 参会人员：用户代表、技术负责人）
  - 紧急程度：P0（基于会议要求"尽快用上"且预算11周交付周期，判断为高优先级）

## 2. 核心目标与价值

- **业务目标**:

    - 系统采用率达到100%（替代现有分散工具）（来自会议纪要 - 风险3：用户接受度问题）

- **成功标准**: 
  - [ ] 支持任务CRUD全流程，包括创建、分配、更新、完成、状态流转（来自会议纪要 - MVP功能范围）
  - [ ] 提供列表视图和看板视图，支持拖拽操作和视图切换（来自会议纪要 - 1.7 任务视图与展示方式）
  - [ ] 实现任务内评论、@提及、系统内通知功能（来自会议纪要 - 1.5 任务分配与提醒机制）
  - [ ] 支持Sprint管理，包括Sprint创建、任务关联、Sprint看板（来自会议纪要 - 1.2 核心业务场景）
  - [ ] 系统响应时间满足性能指标（页面加载<3秒，任务操作<500ms）（来自会议纪要 - 2.1 性能指标要求）
  - [ ] 私有化部署成功，数据完全在企业内网（来自会议纪要 - 3.1 数据存储地域要求）
  - [ ] 团队成员接受培训并能够独立使用系统（来自会议纪要 - 风险应对措施）

## 3. 主要功能范围

### 核心功能模块

#### 功能模块1：用户与权限管理
- **功能描述**：管理团队成员账号和权限，支持简单的角色分配（来自会议纪要 - 2.4 用户认证与权限）
- **核心能力**：
  - 账号密码登录（HTTPS加密传输，BCrypt密码加密存储）
  - 用户注册（管理员审批制）
  - 角色权限管理（管理员/成员两种角色）
  - 会话管理（JWT Token，30分钟过期）

#### 功能模块2：任务管理核心
- **功能描述**：任务的完整生命周期管理，支持创建、分配、跟踪、完成全流程（来自会议纪要 - 1.4 任务生命周期管理）
- **核心能力**：
  - 任务CRUD操作（创建、编辑、删除）
  - 任务属性管理：标题、描述、负责人、截止时间、优先级、状态、标签
  - 任务状态流转：待办→进行中→完成（支持任务重新打开）
  - 任务依赖关系：支持阻塞关系标注（A任务阻塞B任务）
  - 任务操作历史记录（状态变更、属性修改）

#### 功能模块3：多视图展示
- **功能描述**：提供列表和看板两种视图，满足不同使用场景（来自会议纪要 - 1.7 任务视图与展示方式）
- **核心能力**：
  - 列表视图：支持排序、筛选、分组、分页
  - 看板视图：按状态分列（待办/进行中/完成），支持拖拽更新状态
  - 视图切换：顶部Tab切换，记住用户偏好
  - 响应式设计：移动端自适应（320px-1920px）

#### 功能模块4：搜索与筛选
- **功能描述**：快速定位任务，支持多维度筛选（来自会议纪要 - 1.8 搜索与筛选能力）
- **核心能力**：
  - 关键词搜索（搜索任务标题和描述）
  - 快捷筛选器（我的任务、今日到期、本周任务、已完成）
  - 高级筛选（状态、负责人、优先级、标签的多条件组合）
  - 筛选器持久化（记住用户的筛选偏好）

#### 功能模块5：协作与通知
- **功能描述**：任务内协作沟通，减少信息散落（来自会议纪要 - 1.5 任务分配与提醒机制）
- **核心能力**：
  - 任务内评论（支持Markdown格式）
  - @提及功能（通知相关人员）
  - 系统内消息通知（顶部消息铃铛+红点提示）
  - 消息中心（展示所有通知，支持已读/未读状态）
  - 通知场景：任务分配、任务更新、@提及、评论回复

#### 功能模块6：Sprint管理（敏捷开发支持）
- **功能描述**：支持敏捷开发的Sprint迭代管理（来自会议纪要 - 1.2 核心业务场景）
- **核心能力**：
  - Sprint创建和管理（名称、开始时间、结束时间、目标）
  - 任务关联Sprint（将任务分配到特定Sprint）
  - Sprint看板视图（按Sprint查看任务进度）
  - Sprint基础统计（已完成/进行中/待办任务数量）

### 功能边界（明确不做什么）

- ❌ 不包含：Git集成（关联代码提交记录）- 延后到二期实现（来自会议纪要 - 风险2：Git集成技术难度）
- ❌ 不包含：CI/CD集成（关联构建状态）- 延后到二期实现
- ❌ 不包含：邮件通知 - MVP仅支持系统内通知（来自会议纪要 - 1.5 任务分配与提醒机制）
- ❌ 不包含：移动端原生App - MVP仅支持响应式Web（来自会议纪要 - 2.5 移动端支持）
- ❌ 不包含：日历视图和甘特图 - 延后到后续迭代（来自会议纪要 - MVP功能范围总结）
- ❌ 不包含：任务模板和批量操作 - 二期功能（来自会议纪要 - 二期功能规划）
- ❌ 不包含：统计报表和数据导出 - 二期功能
- ❌ 不包含：自定义工作流和自定义字段 - 长期规划
- ❌ 不包含：AI智能推荐 - 长期规划

## 4. 涉及用户角色

### 主要用户角色

#### 角色1：团队成员（开发者/测试者）
- **核心诉求**：
  - 清晰了解自己的任务清单和优先级（来自会议纪要 - 1.3 核心协作痛点）
  - 快速更新任务状态，反馈进度
  - 在任务内与同事沟通，避免信息散落
  - 查看任务依赖关系，了解阻塞情况
- **使用场景**：
  - 场景1：每天早上查看"我的任务"列表，规划当日工作
  - 场景2：完成一个任务后，拖拽到"完成"列，并在评论中@通知下一环节的同事
  - 场景3：在任务详情页查看设计稿、需求文档链接，进行评论讨论

#### 角色2：项目经理/Team Leader
- **核心诉求**：
  - 实时掌握项目整体进度和每个成员的工作状态（来自会议纪要 - 1.3 核心协作痛点）
  - 快速分配任务，明确责任人和截止时间
  - 识别项目风险（任务延期、依赖阻塞）
  - 查看Sprint燃尽图和完成情况
- **使用场景**：
  - 场景1：在看板视图中查看项目整体进度，识别瓶颈任务
  - 场景2：创建新任务并分配给团队成员，设置优先级和截止时间
  - 场景3：每周Sprint回顾会议前，查看Sprint统计数据

#### 角色3：系统管理员
- **核心诉求**：
  - 管理团队成员账号和权限（来自会议纪要 - 2.4 用户认证与权限）
  - 查看系统操作日志，追溯关键操作
  - 配置系统参数，维护系统稳定运行
- **使用场景**：
  - 场景1：新员工入职时创建账号并分配权限
  - 场景2：员工离职时禁用账号，转移其负责的任务
  - 场景3：定期查看操作日志，审计关键操作

## 5. 技术约束与考量

### 性能要求

- **响应时间**：
  - 页面首次加载：< 3秒（来自会议纪要 - 2.1 性能指标要求）
  - 任务列表查询：< 1秒
  - 任务创建/更新：< 500ms
  - 数据库响应时间：< 200ms
- **并发量**：支持100并发用户（来自会议纪要 - 2.1 性能指标要求）
- **可用性**：系统可用率≥99%（基于SaaS服务标准补充）

### 安全标准

- **数据加密**：
  - 传输加密：HTTPS（TLS 1.2+）（来自会议纪要 - 3.2 用户数据隐私保护）
  - 密码存储：BCrypt哈希加密
  - 会话管理：JWT Token，30分钟过期
- **访问控制**：
  - 基于角色的权限管理（RBAC）：管理员/成员（来自会议纪要 - 2.4 用户认证与权限）
  - 任务权限：创建者和负责人可编辑，其他人只读
- **安全防护**：
  - 登录失败锁定机制（5次失败锁定30分钟）（基于OWASP安全标准补充）
  - SQL注入防护（参数化查询）
  - XSS跨站脚本过滤（来自会议纪要 - 3.2 安全措施）
- **审计日志**：
  - 记录关键操作：登录、登出、密码修改、任务创建/更新/删除、权限变更（来自会议纪要 - 3.3 审计与日志要求）
  - 日志保留：30天
  - 日志查询：管理员后台查看

### 集成要求

- **现有系统对接**：
  - Git集成（GitHub/GitLab API）：延后到二期实现（来自会议纪要 - 风险2）
  - CI/CD集成：延后到二期实现
- **数据交换格式**：RESTful API + JSON（基于现代Web应用标准补充）
- **第三方服务**：【待确认：是否需要对接企业通讯工具（钉钉/企业微信）】

### 部署与运维要求

- **部署方式**：私有化部署，数据完全在企业内网（来自会议纪要 - 3.1 数据存储地域要求）
- **部署位置**：公司机房内网服务器
- **访问方式**：仅限公司内网或VPN访问
- **架构方案**：
  - Web服务器：Nginx（负载均衡 + 反向代理）（来自会议纪要 - 2.2 并发用户规模）
  - 应用服务器：2台Spring Boot实例（主备）
  - 数据库：PostgreSQL主从复制
  - 缓存：Redis缓存热点数据
  - 监控：Prometheus + Grafana
- **备份策略**：
  - 备份频率：每日凌晨2点全量备份（来自会议纪要 - 2.3 数据安全与备份）
  - 保留策略：最近7天全量备份
  - 存储位置：独立备份服务器
  - 恢复演练：每月一次备份恢复测试

### 技术栈

- **后端技术栈**：
  - 语言框架：Java 17 + Spring Boot 3.x（来自会议纪要 - 技术选型建议）
  - 数据库：PostgreSQL 15（支持JSON字段，扩展性好）
  - 缓存：Redis 7.x（会话管理、热点数据缓存）
  - 认证：Spring Security + JWT
  - API风格：RESTful API
- **前端技术栈**：
  - 框架：Vue 3 + TypeScript（来自会议纪要 - 技术选型建议）
  - UI组件库：Element Plus（成熟稳定，中文文档友好）
  - 状态管理：Pinia
  - 构建工具：Vite
  - 响应式布局：TailwindCSS

### 风险与制约因素

#### 高优先级风险

- **风险1：开发周期紧张** 【P0】
  - 描述：11周工期需要完成MVP全部功能，时间压力较大（来自会议纪要 - 风险1）
  - 影响：可能导致功能删减或质量妥协
  - 应对措施：严格控制范围，避免需求蔓延；采用敏捷开发，每两周一个迭代；关键功能优先开发

- **风险2：用户接受度问题** 【P1】
  - 描述：团队成员可能不习惯新系统，继续使用旧工具（来自会议纪要 - 风险3）
  - 影响：系统采用率低，无法达成业务目标
  - 应对措施：邀请用户代表参与设计和测试；提供详细培训和文档；分阶段迁移；管理层强制推广

- **风险3：Git集成技术难度** 【P1】
  - 描述：Git集成可能存在技术难点，影响进度（来自会议纪要 - 风险2）
  - 影响：如果纳入MVP会延长交付时间
  - 应对措施：Git集成降为二期功能，MVP暂不包含；提前进行技术预研和POC验证

#### 中优先级风险

- **风险4：私有化部署运维压力** 【P2】
  - 描述：公司IT部门可能没有足够的运维能力（来自会议纪要 - 风险4）
  - 影响：系统上线后故障恢复慢，影响可用性
  - 应对措施：提供详细部署和运维文档；提供3个月技术支持；设计自动化部署脚本；监控告警及时发现问题

- **风险5：性能问题** 【P2】
  - 描述：随着数据量增长，性能可能下降（来自会议纪要 - 风险5）
  - 影响：用户体验下降，影响系统采用率
  - 应对措施：数据库索引优化；分页查询，避免全表扫描；Redis缓存热点数据；定期性能监控
