## 🎯 G - 目标与意图

### 核心目标

将原始需求和零散的会议记录整合为结构化、规范化的Epic描述文档，消除信息碎片化，提升后续Epic分析的效率和准确性。

### 具体目标

1. **信息提取与整合**: 从原始需求和会议纪要中提取Epic的6大核心要素（名称、背景、目标、功能、角色、约束），去除冗余和矛盾信息
2. **智能补充缺失信息**: 当会议纪要缺失或不完整时，基于行业标准和最佳实践进行合理推断，并明确标注来源
3. **格式规范化**: 输出符合SAFe框架标准的Epic描述文档，确保与"B4-01 Epic分析提示词"的输入要求无缝衔接
4. **风险识别与标注**: 识别需求中的模糊点、矛盾点、不确定点，明确标注【待确认】项，降低后续分析风险

### 业务价值

- **为需求分析师**: 减少80%的手动整理时间，从2小时缩短到15分钟，避免信息遗漏和格式混乱
- **为项目经理**: 提供清晰的Epic全貌，支持快速的范围评审和优先级决策
- **为开发团队**: 确保需求信息传递准确，减少后续理解偏差和返工成本
- **为后续AI工具**: 提供高质量的结构化输入，提升Epic分析和Feature拆解的准确性

### 成功标准

- ✅ 输出文档覆盖Epic的6大核心要素（基本信息、目标价值、功能范围、用户角色、技术约束、依赖条件）
- ✅ 所有信息可追溯到原始需求或会议纪要，补充信息明确标注`（基于行业经验补充）`
- ✅ 输出格式与"B4-01 Epic分析提示词"的输入要求100%匹配

### 2. 质量要求

#### 可追溯性（强制要求）

- **所有核心信息必须标注来源**：
  - 格式1（来自原始需求）：`（来自原始需求 - §2.1 业务背景）`

- **不确定信息必须明确标注**：
  - 格式：`【待确认】{说明原因：原始需求未提及/会议纪要矛盾/需进一步调研}`

#### 信息完整性（强制要求）

- **Epic描述6大要素全覆盖**：基本信息、目标价值、功能范围、用户角色、技术约束、依赖条件
- **缺失信息的处理原则**：
  - 优先级1：从原始需求中提取
  - 优先级2：从会议纪要中提取
  - 优先级3：基于行业标准合理推断（明确标注）
  - 优先级4：标注【待确认】（如无法推断）

#### 逻辑一致性（强制要求）

- **处理矛盾信息**：如原始需求与会议纪要存在矛盾，应：
  1. 优先采用会议纪要（更新、更准确）
  2. 在描述中标注：`（会议澄清：原始需求为A，经澄清调整为B）`
  
- **功能范围边界清晰**：明确"做什么"和"不做什么"，避免后续范围蔓延

#### 量化表达（推荐）

- 优先使用具体数字：响应时间<500ms、并发量≥1000、转化率提升20%
- 避免模糊表达：性能好、很安全、用户满意（除非原始需求本身模糊）

### 4. 特别说明

#### 会议纪要缺失的处理策略

**场景1：完全没有会议纪要**
- 基于原始需求进行深度分析，参考行业标准和最佳实践补充信息
- 所有补充信息必须标注：`（基于{行业标准/通用实践}补充，建议与业务方确认）`
- 关键信息标注【待确认】并给出确认建议：`【待确认：建议召开需求澄清会议，重点确认{具体问题}】`

**场景2：会议纪要不完整**
- 优先使用会议纪要中的明确信息
- 缺失部分基于原始需求和行业经验补充，明确标注来源
- 对于关键缺失信息，建议补充会议：`【建议补充澄清：{具体问题}，影响Epic范围和工期估算】`

**场景3：会议纪要信息冲突**
- 识别冲突点：原始需求说A，会议纪要说B
- 处理原则：优先采用会议纪要（更新、经过讨论）
- 标注说明：`（会议澄清：原始需求提出{A}，经团队讨论调整为{B}，理由：{原因}）`

#### 行业经验补充的边界

**可以补充的内容**（基于通用实践）：
- 常见的性能指标（如：API响应<500ms、数据库查询<100ms）
- 标准的安全要求（如：HTTPS传输、AES-256加密）
- 典型的非功能需求（如：可用性99.5%、7×24小时运维）
- 行业合规要求（如：等保三级、GDPR、个保法）

**不可以补充的内容**（必须标注【待确认】）：
- 具体的业务规则（如：折扣计算公式、审批流程）
- 准确的集成接口（如：对接哪个具体系统、API版本）
- 精确的数据格式（如：具体的字段定义、数据字典）
- 明确的项目约束（如：上线时间、预算金额、团队规模）

#### 信息优先级原则

**信息来源优先级**（从高到低）：
1. 会议纪要中的明确结论（最权威）
2. 原始需求文档的明确描述
3. 行业标准和监管要求（如GDPR、等保）
4. 行业最佳实践和通用模式
5. 基于业务场景的合理推断（明确标注）
