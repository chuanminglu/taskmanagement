> **📌 使用说明**: 本提示词用于基于用户故事列表，生成用户旅程关键阶段。建议在设计元素分析前使用本提示词。

- 用户行为流程分析与阶段划分

- 能够从离散的用户故事中抽象出完整的用户旅程

## 🎯 G - 目标与意图

### 核心目标

从离散的用户故事中抽象出连贯的用户旅程，明确关键阶段和决策点，为后续的UI设计和原型开发奠定基础。

### 具体目标

1. **流程清晰化**: 将用户故事按时间顺序排列，形成完整的用户任务流
2. **阶段识别**: 识别用户旅程中的关键阶段（如初始化、信息填写、确认提交等）
3. **映射完整性**: 确保每个用户故事都映射到旅程中的某个阶段
4. **决策点明确**: 标识用户做出的关键决策和系统给予的反馈

### 业务价值

- **为UI设计师**: 理解用户的完整任务流，确保页面设计覆盖所有关键场景
- **为产品经理**: 验证用户故事的逻辑完整性，识别可能遗漏的故事
- **为开发团队**: 理解功能之间的关联和先后顺序，支持开发规划
- **为测试团队**: 提供端到端的测试场景和验证路径

### 成功标准

- ✅ 用户旅程包含5-8个关键阶段，覆盖从开始到完成的全流程
- ✅ 每个阶段都映射了1个或多个用户故事，无故事遗漏
- ✅ 阶段间有明确的先后顺序和依赖关系
- ✅ 识别了关键决策点和系统反馈触发点

### 2. 质量要求

#### 完整性（强制）

- ✅ 旅程包含用户故事列表中100%的故事
- ✅ 每个阶段的目标、行为、系统反馈都清晰明确
- ✅ 关键决策点完整，无遗漏

#### 逻辑一致性（强制）

- ✅ 阶段顺序符合用户的实际操作流程（不能颠倒）
- ✅ 前后阶段有清晰的因果关系和衔接
- ✅ 决策点的逻辑分支清晰

#### 可追溯性（强制）

- ✅ 每个阶段标注关联的用户故事ID
- ✅ 格式：`（US-01、US-02）`

### 4. 特别说明

#### 识别关键阶段的方法

```
方法1: 按用户任务目标分组
- 用户故事US-01、US-02的共同目标：选择系统
  → 识别为"系统选择阶段"

方法2: 按用户行为类型分组  
- 数据查看：US-08（查看历史需求）
- 数据输入：US-04、US-05（填写需求信息）
- 数据提交：US-06（提交需求）
  → 可识别为三个不同的阶段

方法3: 按系统状态转移分组
- 初始化：系统加载、数据准备
- 交互：用户与系统交互
- 完成：任务完成或返回

推荐方法: 结合以上方法，找到最自然的阶段划分
```

#### 常见错误修正

❌ **错误1**: 阶段划分过细（20+个阶段）

```
错误：每个故事一个阶段，阶段数量过多
正确：合并同类故事，控制在5-8个阶段
```

❌ **错误2**: 忽视用户故事间的依赖关系

```
错误：故事US-03（选择模板）在US-01（选择系统）之前
正确：系统选择必须先于模板选择，体现依赖关系
```

❌ **错误3**: 决策点不清晰

```
错误：阶段后"可能进入下一阶段"（太模糊）
正确：明确列出所有可能的分支和触发条件
```

#### 无用户旅程的处理方案

如果没有现成的用户旅程，使用以下步骤：

1. **阅读用户故事列表**，识别共同的用户目标
2. **按时间顺序排列**，找到自然的流程顺序
3. **识别关键转折点**，确定阶段边界
4. **补充系统反馈**，描述系统在每个阶段的响应
5. **验证完整性**，确保每个故事都被覆盖
