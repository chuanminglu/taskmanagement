# AI编程流程规划提示词 V2.0

> **📌 使用说明**: 本提示词用于基于任务特征规划AI编程执行模式，识别适合Subagent自主执行的任务，生成Subagent Prompt模板，最大化AI编程效率。
>
> **前置输入**: 任务列表（来自3-任务拆解与估算提示词）、代码库现状
>
> **预计时长**: 30分钟-1小时
>
> **核心价值**: 🌟 这是AI赋能DevOps的核心创新点，通过智能规划让AI最大化参与开发工作
>
> **版本说明**: V2.0相比V1.0增加了适用条件、量化分类标准、工具链方案、效果度量、风险管理、成本效益分析，显著提升可操作性。

## 📋 适用条件（使用前必读）

> ⚠️ **请先完成以下检查，若必要条件未满足，建议延后使用本方案。**

### ✅ 必要条件（全部满足才能使用）

- [ ] 项目已运行≥3个Sprint，有基础代码库可参考
- [ ] 有明确的编码规范文档（或代码风格可从现有代码学习）
- [ ] 有CI/CD流水线（至少支持编译和自动化测试）
- [ ] 团队中至少1人有AI编程工具使用经验
- [ ] 管理层理解这是"投资"而非"速效药"（首个Sprint可能负收益）

### ⚠️ 次要条件（满足越多越好）

- [ ] 有至少1个模块的完整参考实现（含单元测试）
- [ ] 有完整的技术设计文档（API契约、数据库设计等）
- [ ] 项目周期≥6个月（至少有4个Sprint可以摊销学习成本）
- [ ] 团队规模≥5人（投入产出比更合理）

### ❌ 不适用场景

| 场景 | 原因 | 建议 |
|------|------|------|
| 新项目第1-2个Sprint | 无参考代码，AI输出质量无法保证 | 先建立代码基础，第3个Sprint再试点 |
| 遗留系统改造（无测试） | AI可能学习到坏实践，且无法验证 | 先建立测试覆盖，再引入AI |
| 紧急交付（deadline<1周） | 没有容错空间 | 下个Sprint尝试 |
| 团队<3人 | 投入成本占比过高 | 个人项目先练习，再推广 |
| 全新技术栈（无文档） | 缺少AI需要的背景知识 | 先完成技术调研，再使用 |

### 任务上下文

AI编程流程规划是将任务从"人工执行"转变为"AI辅助执行"或"AI自主执行"的关键步骤。

**核心理念**：
- 不是所有任务都适合AI
- 不是所有AI任务都需要人工监督
- **合理分类 + 持续优化** 才能真正提升效率
- 效率提升需要时间积累，**首个Sprint可能是负收益**（正常现象）

**执行模式分类**：

| 模式 | 标记 | 说明 | 实际效率提升（成熟期） |
|------|------|------|----------|
| Subagent自主 | 🟢 | AI独立完成，人工只做最终review | **50-70%** |
| 人机协作 | 🟡 | AI生成初版，人工调整关键逻辑 | **30-40%** |
| 人工主导 | 🔴 | 人工为主，AI辅助补全/查询 | **10-20%** |
| AI辅助调研 | 🟣 | AI收集信息，人工决策 | **60-70%** |

> ⚠️ **注意**：上述数字是成熟期（4+个Sprint后）的预估值。首个Sprint预计效率提升为负，第2-3个Sprint逐步回正。

## 🎯 G - 目标与意图

### 核心目标

为Sprint任务制定**最优的AI执行策略**，让AI最大程度参与开发工作，同时确保代码质量和项目可控。

### 具体目标

1. **任务分类客观**: 基于量化评分（而非主观判断）为每个任务选择执行模式
2. **Prompt可执行**: 🟢任务的Subagent Prompt完整、可直接执行，包含工具使用指引
3. **协作流程清晰**: 🟡任务有明确的人机协作流程、决策点和迭代上限
4. **效率可度量**: 输出效率跟踪模板，支持实际数据记录和改进

### 业务价值

- **为开发团队**: 减少重复性编码工作，聚焦高价值任务
- **为项目经理**: 提升团队产能，更快交付（成熟后40-60%效率提升）
- **为技术Leader**: 建立AI编程最佳实践，提升团队AI能力
- **为组织**: 探索AI赋能的新型开发模式，建立竞争优势

### 成功标准

- ✅ 所有任务通过量化评分完成分类
- ✅ 🟢任务有完整的Subagent Prompt（含工具使用指引）
- ✅ 🟡任务有明确的协作流程和迭代上限
- ✅ 执行批次考虑依赖关系（无真正"并行"，而是考虑前置任务）
- ✅ 效率跟踪模板可立即使用
- ✅ 风险已识别并有应对措施

> **使用以下4维度评分为每个任务打分，确保分类客观一致。**

#### 评分维度

| 维度 | 5分 | 3分 | 1分 | 权重 |
|------|-----|-----|-----|------|
| **输入明确度** | 有API契约+详细设计文档 | 有User Story+验收标准 | 只有口头描述 | 30% |
| **参考可用度** | 有完全相同的实现可参考 | 有类似模块参考 | 全新开发，无参考 | 25% |
| **复杂度** | 纯CRUD/标准配置 | 标准业务逻辑 | 算法/架构设计 | 25% |
| **验证难度** | 自动化测试可完全验证 | 手动测试可验证 | 需专家人工评审 | 20% |

- **18-20分** → 🟢 Subagent自主

| Prompt设计耗时超预期 | 中 | 高 | 复用已有模板，首次预留额外1h | Prompt设计>预估2倍 |
| AI服务不可用 | 高 | 低 | 切换为人工执行，不影响交付 | AI服务连续2h不可用 |
| 🟡任务迭代超限 | 中 | 中 | 超过3轮立即转人工主导 | AI调整轮次=3且未通过 |

### 熔断机制

当出现以下情况时，**立即暂停Subagent执行，转为传统人工方式**：

- 🔴 连续3个🟢任务Review不通过
- 🔴 Sprint中期（Sprint的50%时间点）进度延迟>20%
- 🔴 AI服务连续2小时不可用
- 🔴 团队信心明显下降（日站会反映问题）

### 2. 质量要求

#### Prompt完整性（强制）

每个🟢任务的Subagent Prompt必须包含：

| 要素 | 是否必需 | 检查方法 |
|------|----------|----------|
| 任务背景 | ✅ 必需 | 能否让陌生人理解任务上下文？ |
| 任务目标 | ✅ 必需 | 是否列出具体产出？ |
| 参考文档路径 | ✅ 必需 | 路径是否正确且文件存在？ |
| 参考代码路径 | ✅ 必需（有时） | 如果有类似实现，必须提供 |
| 输出要求（文件列表） | ✅ 必需 | 是否列出所有需要创建的文件？ |
| 代码规范 | ✅ 必需 | 是否具体可执行（非"风格一致"这类模糊描述）？ |
| 约束条件 | ✅ 必需 | 是否说清楚不能做什么？ |
| 工具使用指引 | ✅ 必需 | 是否说明如何读取参考文件？ |
| 验收标准 | ✅ 必需 | 是否可执行（能运行命令验证）？ |

#### 分类客观性（强制）

任务分类必须填写完整的评分表，不允许直接主观判断：

❌ **错误做法**：
```
Task-001：这是个简单任务，标记为🟢
```

✅ **正确做法**：
```
Task-001：输入明确度5分（有API契约）+ 参考可用度5分（有UserService.java参考）
          + 复杂度5分（纯CRUD）+ 验证5分（有单元测试框架）= 20分 → 🟢
```

#### 效率数据真实性（强制）

- AI工时估算**必须包含**：Prompt设计时间（0.3-0.5h）+ Review时间（0.5-1h）+ 预估修复时间
- **禁止使用**不含隐性成本的"生成时间"作为AI工时
- 效率提升**必须注明**这是成熟期（4+个Sprint后）的预估

### 3. 格式规范

- 文档格式：Markdown
- Prompt格式：使用代码块（三个波浪线）包裹，便于复制
- 评分表：使用表格
- 流程图：使用ASCII图或Mermaid
- Emoji：🟢/🟡/🔴/🟣表示执行模式，✅/❌/⚠️表示状态

### 4. 特别说明

#### 关于"并行Subagent"

原始V1.0中提到"T001和T003并行执行"。

**现实情况**：
- 当前的AI编程工具（GitHub Copilot、Claude等）不支持真正的并行Subagent
- 开多个Chat窗口执行会导致Review积压，适得其反
- **建议**：串行执行，每个任务立即Review完再执行下一个

#### 关于效率预期

**首个Sprint（学习期）**：
- 实际效率可能为负（Prompt设计比直接写代码还慢）
- 这是正常的，不要因此放弃
- 重点是积累经验，而不是追求效率

**第2-3个Sprint**：
- 可以开始复用Prompt模板
- 效率开始逐步提升
- 预期可达到20-30%效率提升

**第4+个Sprint（成熟期）**：
- Prompt模板库成熟，设计成本大幅降低
- 🟢任务效率提升可达50-70%
- 此时的数字才是可以对外声称的

#### 信息不足的处理

如果材料中缺少某些信息（如参考代码路径），应该：
1. **明确标注缺失信息**：在Prompt中用`{待补充: XXX}`标注
2. **提供替代建议**：建议提供某个现有文件作为参考
3. **降低执行模式**：缺少关键信息时，建议从🟢降为🟡，待信息补充后再升级
